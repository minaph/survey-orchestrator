# プロット・読者理解・監査のレビュー基準

この文書は、G5/G6でサーベイ資料の意味、読者の理解、公開可否を判断し、その根拠を記録するための基準です。構造検査で確認できる事実と、レビュー担当者が判断する内容を分けます。構成の明瞭さ、概念の境界、再構成図の忠実性は、スクリプトの合格だけでは確定できません。

## 評価順序と判断の分担

1. 監査メタデータを見る前に、プロットと完成資料を読者として読みます。
2. 出典の支持、概念の境界、不確実性、統合、転用、RRMの関係、原図・再構成の忠実性を確認します。
3. 成果物と監査記録の決定論的な事前検査を実行、または結果を確認します。
4. 意味上の指摘、形式上の指摘、修正結果を合わせて公開可否を判断します。

整ったマニフェスト、引用件数、監査資料の量を読者理解の根拠にしません。読者向けの構成が良好でも、主張の支持や出典忠実性の問題は残ります。

### 決定論的・形式的な検査

スクリプトは、スキーマ・必須項目、IDと結合、経路整合、パス、経路に基づくハッシュ、時刻、有限数値領域、表・図・グラフ構造、ページ対応、観測された文字・図形、対応可能なはみ出し・衝突・欠字、引用や内部語の抽出を確認します。

```text
deterministic_status: passed | blocked | pending
checks_run, required_checks, failures, warnings
coverage: population, target, checked, denominator, seed, exclusions
```

この一覧は検査結果を説明する論理属性です。検査の方法や標本抽出を適用した範囲で記録し、常時全項目を埋めるフォームにはしません。形式チェッカーへ渡す記録は、そのチェッカーが要求する状態・範囲・結合を別途満たします。

検査範囲は実施内容の集計です。現在のチェッカーが実施した範囲と予定範囲を分けます。PPTXの幾何検査やPDFの文字・物体観測が、PDFの切れ・衝突・画像内文字・CJK・全派生素材の完全検査を保証するわけではありません。

### 意味・内容のレビュー

出典が読者の文言を支持するか、概念間の区別が妥当か、図が関係・単位・条件・比較・不確実性・null・限界を保持するかを判断します。構成・ナビゲーション・統合・転用が対象読者に適するか、出典の結果と分析者の解釈・推奨を分けているか、監査情報が理解を妨げていないかも確認します。再利用の権利判断は、実際の制限、出典同一性の不明、第三者の権利、方針上の問題がある場合に検討します。

`semantic_status`、`fidelity_status`、`visual_review_status`は項目ごとの根拠箇所・修正とともに分けて記録します。マニフェストの`passed`宣言だけでは実施の証拠になりません。形式検査は記録と結合の整合性を確認できても、決定論的な合格を意味上の合格に変換しません。モデルにレビューを任せる場合は、実レンダリングを観察し、視覚的意味を判断できる能力が当該作業で確かめられている必要があります。

## レビュー資料と検査母集団

G5/G6では、次の順に資料を示します。

| 資料 | 内容 | 判断上の役割 |
|---|---|---|
| 読者向け資料 | プロット、レンダリング済み成果物、読者に見える出典 | 理解と構成を先に評価します |
| 学術・出典忠実性資料 | 主張、出典所在、原図切り抜き、再構成資料、境界記録 | 文言と根拠、図と出典を照合します |
| 監査・事前検査資料 | チェッカー結果、結合、ハッシュ、時刻、観測計測、範囲集計 | 形式整合と検査の限界を確認します |

G6では、中心主張、数値主張、境界・矛盾の事例、リスクの高い主張・転用、出典忠実性を要する図を全件確認します。通常行は事前に宣言した標本で確認でき、例えば各節二件以上、節が小さければ全件とします。母集団、分母、乱数種、対象件数、除外理由をレビュー前に固定し、網羅状況と品質判定を分けて残します。

本文と図の役割分担を確認するG6の母集団は、中心・数値・境界・高リスク主張の図と全ての出典忠実性対象図、および通常行の図の事前標本です。説明・根拠・統合の意味を担う図は、四つの視覚契約に該当するかによらず含みます。G4-Pではこの確認を全計画スライドへ適用します。装飾・ナビゲーションのみの形状は対象外です。説明・根拠・統合の実際の役割が消えた場合に限って対象外へ再分類できます。

レビュアーは指摘、評価、根拠、再確認条件を返し、監督者が修正を管理します。異議や採用しなかった過剰な要求は短い変更記録に残します。

## 意味とストーリーの判定基準

### RRMの関係を辿れるか

中心・高リスクの主張では、意味や強さを変えるRRMの関係を特定します。読者向け資料と参照先から、概念、対象単位・母集団・コーパス、文脈、結果を変える操作・測定・符号化・比較、観測結果・論証、差や関連が確認されなかった結果（null）・矛盾、限界・不確実性・転用条件・未測定事項を辿れるか確認します。

[RRM](rrm.md)の解釈規則に従い、出典の報告結果、方法への評価、研究間の傾向、サーベイの解釈、推奨を区別します。必要で簡潔・明瞭・保守的な橋渡しは、サーベイ上の価値、境界、反証、確実性を資料と参照先で確認できれば許容されます。全項目をスライドへ印刷する必要はありません。出典が想定していない問いへの不足を出典自体の欠陥とせず、サーベイの橋渡しが妥当かを判断します。六つのチェック欄、RRM率、メタデータ充足で置き換えません。

### 全体・節・根拠ブロック・スライド

[プロットの階層と行の意味](storyline-plot.md#階層と対象単位)を使い、次を行・ページごとに検討します。

| 対象 | 判定する問い |
|---|---|
| 全体・節 | 冒頭と結末から問いと回答が分かりますか。各節の局所回答が累積し、次の問いと最終統合へ根拠の飛躍なくつながりますか |
| 位置と進行 | 分野地図、目次への再入場、現在位置、局所的な注目の順序が、どこまで答えたかと何が次かを示しますか |
| 根拠ブロック | 中核研究の問い・対象・条件、方法、実図、結果、比較評価、限界を出典に適する深さで確認でき、局所の回答へつながりますか |
| スライド | 見出しが論文名だけでなく問い・結果を述べ、`T -> B -> Bottom -> Figure -> Next`が一つの説明を形成していますか。役割に必要な情報を、短さや余白のために省いていませんか |
| 意味と転用 | 文言が出典より強くなっていませんか。測定済み・未測定・分析者の解釈、標本・課題・文脈・転用条件が分かりますか |
| 修正可能性 | 不明瞭さを、前提不足、過負荷、図の不適合、移行不良、表示不良のどれとして遡れますか |

[役割別の密度](survey-design-analysis.md#役割に応じて説明の密度を決める)に照らし、概要・橋渡しと研究詳説・横断比較・評価と統合を区別します。根拠を担うページは、タイトルと一言、大きな余白だけでは十分と判断しません。読者が「何をどの条件で行ったか」「図のどこに結果があるか」「評価が何に基づき、どこまで言えるか」を説明できるか確認し、不足ならその箇所へ戻します。必要な説明を連続ページで分担することは許容しますが、監査資料にだけ置かれた方法・条件で読者向けの不足を補った扱いにはしません。図数、図面積、文字数の閾値や新しい採点軸は増やしません。

### 本文と図の役割

図がプロットで述べた関係を示すか、本文とは別の観察を可能にするかを確認します。本文を除き、図内のラベル・軸・凡例・注記・キャプション・クレジットを残して何を観察できるか述べます。次に図を除いて、本文が留保・限界を含め何を主張するか述べます。図を複数載せる場合は、各図の観察と共同で支える比較・回答、各出典と帰属を確認します。このテストは本文と図がそれぞれ完全な説明を繰り返すことを要求せず、相互の寄与を判断するために使います。

本文の言い換えに留まる図や、評価を読み取れない並置では、必要な実図・方法・条件・結果・留保を先に点検します。根拠を維持する配置、拡大、詳細ページとの連携、再設計を検討し、寄与しない要素は削除・保留・再分類できます。異なる課題・データ・尺度・条件の結果について、共通の見た目や数値だけで優劣を断定していないかも確認します。

原図・再構成図・サーベイ独自の図の帰属が読み取れるかも確認します。実際の表示と表の意味照合は[視覚レビュー](visual-review.md)、役割・経路・キャプション・要素対応の忠実性は[再構成レビュー](reconstruction-review.md)で確認します。ここではその結果を公開判断へ反映し、細則を複製しません。

## 相殺できない公開条件

次の条件は得点で相殺できません。

- 中心の問いと結論が理解でき、中心・数値・境界・矛盾・高リスク転用の主張に根拠があります。
- 概念の境界と隣接概念との差が妥当で、中心主張の意味を変えるRRMの関係と境界を辿れます。
- 出典の報告結果、サーベイの統合、推奨を混同していません。`claim_role`で統合を記録する場合は`cross_study_pattern`または`survey_interpretation`へ対応づけます。
- 意味を担う図に本文と異なる役割と観察可能な寄与があり、再構成・出典に基づく統合が[再構成レビュー](reconstruction-review.md)の経路別要件を満たします。
- 監査情報の混入が理解を実質的に妨げず、必要な決定論的監査・成果物検査に合格しています。

未解決または不合格は`blocked`または`pending`とします。`not_applicable`には明示的な作業設定と理由が必要です。表示や投影に固有の公開阻害要因は[視覚レビュー](visual-review.md#公開を妨げる表示上の問題)を適用します。

## 読者向け品質の得点

公開条件を確認した後、必要な場合だけ採点で読者向け品質を要約します。以下の100点配点は、選択できる任意の評価プロファイルの一例です。全ての作業でこの軸・配点を採用する必要はなく、独立した合否や公開状態を左右しません。得点は意思疎通の補助で、メタデータ追加の報酬ではありません。

| 評価軸 | 配点 | 判断内容 |
|---|---:|---|
| 図の役割と可読性 | 30 | 強調・階層・関係から主張を見取れるか |
| 構成の一貫性と統合 | 25 | 局所回答が妥当な結論へ累積するか |
| ナビゲーションと位置づけ | 15 | 節の位置、移行、次の問いを辿れるか |
| 転用と適用可能性 | 15 | 示した境界内で結果を利用できるか |
| 根拠表示と主張・図の適合 | 10 | 方法・結果・比較・境界が可視化されているか |
| アクセシビリティ・投影・可搬性 | 5 | 対象読者が完成資料を読み、使えるか |

採点する場合は、選択した評価軸ごとの判断を正本にします。`dimensions`を記録するならその表示値を、`denominator`には適用する配点の合計を、`score`には合計得点を分母で割った0〜100の正規化値を算出します。同じ判断から展開し、三つの値を独立して手動更新しません。この例では全軸を適用すると分母は100です。定義上該当しない軸だけ除外して正規化します。

現行のレビュー記録チェッカーは`score`を必須にしません。省略時は厳格な検査でも注意を返すだけで、不合格にはなりません。記録する場合は有限の0〜100の値と、正の有限値の`denominator`が必要です。`dimensions`の記載・配点・合計・正規化の整合性はチェッカーの検査対象外なので、選択したプロファイルと算出結果を照合します。採点しない場合は三項目を埋めるためだけの評価を作りません。

ID、ハッシュ、担当者の役割、境界の説明量、監査資料の大きさには加点しません。境界の妥当性は公開条件、読者がその帰結を理解できるかは構成と転用の評価で扱います。

## レビュー記録と公開判断

### 状態・評価・指摘の単位

以下の記録項目は、適用されるレビューと記録形式に応じて使います。発表資料の正式なチェッカー入力には`plot_review`・`reader_review`、版、行・ページ範囲、適用状態の記録が必要ですが、全ての論理属性が常時必須という意味ではありません。例えば、`scope.items`は主張・図の所在を使う場合、各指摘の詳細は実際に指摘を記録する場合、採点項目は採点を選ぶ場合に適用します。スライドのない文章サーベイは、問い・根拠・判断・修正をその文書の所在で記録し、発表用のページや採点値を補作しません。

個別の指摘は`strong`、`adequate`、`fragile`、`blocked`で評価し、根拠箇所、修正、再確認条件を添えます。全体の`plot_review.status`と`reader_review.status`は公開状態です。局所評価が`strong`・`adequate`なら合格し得ますが、中心経路に未解決の`fragile`・`blocked`があれば対応する全体状態を`pending`・`blocked`に保ちます。集約はレビュアーの判断です。

成功した観察を全件`findings`へ列挙する必要はありません。現行チェッカーは`findings`の省略でも厳格な検査に合格できますが、それだけでは意味レビューを実施した証拠になりません。検査範囲と全体判断を残し、修復や意味を変える改訂には、影響する箇所をいつ・何に照らして再確認するかを既存の指摘・変更記録に記載します。

記録する各指摘は、宣言範囲内の`row`とページ、または`claim_or_visual`とページのどちらか一組で特定します。`claim_or_visual`を使う場合はIDを`scope.items`に列挙します。空でない問い、一つの評価、明示的な修正（不要なら`none`）、空でない再確認条件を記録します。チェッカー互換上、指摘を記録する場合の`recheck`は必須です。チェッカーは記録の整合性を確認し、評価そのものの正否は判断しません。

### 記録例

次は全体合格を記録し、上の任意プロファイルで採点した場合の展開例です。例中の回答や得点を実案件へコピーせず、実際のレビュー結果を記述します。採点しなければ`score`・`denominator`・`dimensions`は省略できます。

```json
{
  "plot_review": {
    "status": "passed",
    "plot_version": "v0.3",
    "scope": {
      "coverage": "all",
      "rows": ["P-01", "P-02"],
      "pages": ["slide-1", "slide-2"]
    },
    "findings": [
      {
        "row": "P-01",
        "page": "slide-1",
        "question": "読者は冒頭の問いを説明できますか",
        "verdict": "strong",
        "repair": "none",
        "recheck": "次のレンダリング後に冒頭と結末を再読します。"
      }
    ]
  },
  "reader_review": {
    "status": "passed",
    "scope": {"coverage": "all", "pages": ["slide-1", "slide-2"]},
    "score": 82,
    "denominator": 100,
    "dimensions": {
      "visual": 25,
      "narrative": 21,
      "navigation": 12,
      "transfer": 12,
      "evidence_fit": 8,
      "accessibility": 4
    },
    "findings": []
  },
  "deterministic": {"status": "passed"},
  "semantic": {"status": "passed"},
  "fidelity": {"status": "not_required"},
  "visual_review": {"status": "passed"},
  "release": "passed"
}
```

公開条件は、適用される状態の論理積です。

```text
release = plot review PASS
          AND reader review PASS
          AND deterministic PASS
          AND semantic PASS
          AND fidelity PASS
          AND visual review PASS
```

全ての適用条件を満たした場合だけ公開します。読者得点で中心主張・意味の境界・出典忠実性・監査の未解決事項を相殺せず、監査資料の量で構成・根拠表示・位置づけ・転用の不足を相殺しません。

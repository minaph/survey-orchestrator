# 根拠モデル

## 利用目的と対象範囲

このモデルは、複数の報告・版・抽出結果・対立する主張を扱う文献調査で、読者向けの主張を具体的な根拠まで追跡するために用います。`source/report → work/study → evidence → claim` は概念上の関係です。結合表、JSON、SQLite、少数の台帳など、追跡に必要な最小の保存形式を選べます。

以下は対象の意味と論理項目の定義です。個別の記録には、その定義に照らした値と出典箇所を記載します。RRMの観点と調査側の解釈条件は [rrm.md](rrm.md)、図の機械契約は [evidence-visual-contract.md](evidence-visual-contract.md) を参照してください。

項目一覧は利用できる論理項目を示し、全項目の常時必須入力を求めるものではありません。問いへの回答や主張の意味に必要な情報を保持し、同じ内容は正本への参照や共有文脈の継承で表せます。必要な区別を追跡できれば、個別欄の代わりに出典付きの説明へまとめることもできます。

## 概念・単位・同一性

| 概念 | 意味と一件の単位 | 同一性と区別する対象 | 主な関係 |
|---|---|---|---|
| `source/report`（情報源・報告） | 取得して参照できる文書・データ・成果物。抽出に使った具体的な報告と版を扱います。 | `source_id` と版・取得情報により、参照した報告を識別します。同じ研究を報告するプレプリント、会議論文、雑誌論文、技術報告、データセット、補足資料は、同一の文書としてまとめません。 | 対応する研究と抽出箇所を追跡します。`canonical_id` は同じ研究を報告する文書群を結ぶ既存項目ですが、`work_id` と同じ群を指す場合は二重管理せず、互換性・外部対応が必要なときだけ別名参照や導出値として用います。 |
| `work/study`（研究・論証） | 一つ以上の報告に記述された研究または論証。研究単位の集計では一件と数えます。 | `work_id` は文書の識別子と役割が異なります。複数報告が同じ研究かを確認し、版ごとの相違を残します。調査が報告・版そのものを分析する場合は、その集計単位を明示します。 | `reports[]` が報告群を、`evidence.work_id` が抽出結果の研究を結びます。 |
| `evidence`（根拠） | 主張を支持または限定できる、抽出した結果、論証、方法上の事実、境界、差や関連が確認されなかった結果（null）、反例の一件。 | `evidence_id` は抽出した内容を識別します。内容と出典箇所をそろえて照合し、同じ結果の再掲を独立した支持として数えません。 | `work_id`、`source_ids[]`、`locator` から、元の研究・報告・箇所へ戻れます。複数の主張が同じ根拠を利用できます。 |
| `claim`（主張） | 一つ以上の根拠から組み立てた、読者に示す命題の一件。 | `claim_id` は命題を識別します。読者向けの言い換えと、対象・条件・強さを変える命題の変更を区別します。 | `evidence_ids[]` が支持、`counterevidence_ids[]` が反証・限定材料、境界条件と確実性が適用範囲を示します。 |

同一性が未確認なら、確認できた報告間の対応と不確実性を残します。文献件数を合わせるために研究を統合したり、一つの研究の複数報告を独立研究として扱ったりしないでください。

報告・研究・根拠・主張の単位は、図やページの単位と一致しません。同じ研究の方法図と複数の結果図を紹介しても研究件数は一件です。一つの比較ページに異なる研究の原図を並べても、それぞれの研究・根拠を保持します。図の並置だけを新しい独立研究や支持件数として数えません。図ごとの出典箇所と研究への参照は既存の図契約へ、共同で支える問いと回答はプロットへ置きます。

## 属性と記載責任

### 情報源・報告

```text
source_id, canonical_id (任意), url_or_doi, version, retrieved_at,
source_type, locator (任意)
```

識別・版・取得属性は参照した文書を再確認するために、`source_type` は情報源の役割を区別するために使います。`source.locator` は報告全体の補足位置などが必要な場合の任意項目です。抽出に用いたページ、節、図、表、データ位置の正本は `evidence.locator` に置きます。同じ報告の根拠ごとに情報源を分割しません。研究として数えない背景資料や方法資料は、その位置づけを明示します。

### 研究・論証

```text
work_id, identity, design_or_type, reports[], sample_or_corpus, methods
```

`identity` は研究・論証を区別する内容、`design_or_type` は設計・資料の種類、`sample_or_corpus` と `methods` は対象と方法を保持します。`work.methods` は研究に共通する方法の記載先です。報告間で方法や結果が変わった場合は、使用した版と相違を確認できるようにしてください。

### 根拠

```text
evidence_id, work_id, source_ids[], locator, construct, method_or_basis,
condition_or_comparator, result_or_argument, null_or_counterexample,
limitation, transferability
```

`construct` は対象概念、`method_or_basis` は観察・論証の基盤、`condition_or_comparator` は条件・比較対象を表します。`evidence.method_or_basis` は共通する `work.methods` を参照し、結果固有の手順・分析・条件の差分がある場合に記述します。全文を複写する必要はありませんが、結果の意味を変える方法・条件は、その根拠から辿れるようにします。`result_or_argument` には、情報源で観察または論じられた内容と箇所を記載します。調査側の解釈は主張側へ置き、情報源の結果へ混ぜません。差や関連が確認されなかった結果・反例・限界・転用可能性は、結果の意味を変える範囲で保持します。

### 主張

```text
claim_id, claim_text, claim_type, claim_role (任意), evidence_ids[],
counterevidence_ids[], boundary_conditions[], certainty,
manager_interpretation, reader_wording
```

`claim_type` は論理形式です。少なくとも `descriptive`（記述）、`comparative`（比較）、`causal`（因果）、`normative`（規範）、`methodological`（方法）を区別します。`claim_role` は記述の責任を表し、論理形式とは別に扱います。

| `claim_role` | 意味 |
|---|---|
| `source_reported` | 情報源が報告した内容 |
| `methodological_assessment` | 方法に対する評価 |
| `cross_study_pattern` | 研究間に見いだしたパターン |
| `survey_interpretation` | 調査側による解釈 |
| `recommendation` | 推奨 |

`claim_role` は条件付き項目です。調査側の解釈、推奨、または責任が曖昧になる研究間パターンでは記載してください。同じ比較命題でも、情報源による報告と調査側による比較解釈では責任が異なります。`manager_interpretation` は解釈、`reader_wording` は読者に示す表現を保持します。文脈のための情報源引用と、命題を支える具体的な根拠の参照も区別してください。

`claim_text`、`manager_interpretation`、`reader_wording` に同じ内容を独立に複写する必要はありません。命題は一箇所を正本とし、橋渡しの説明や読者向けの言い換えに意味・表現上の差が必要な場合だけ別に記載します。参照や同じ記録への統合を使う場合も、出典の結果と調査側の解釈の責任を明示し、この区別を保ってください。

研究の的確な要約には、研究の対象・方法と、根拠の条件・結果・限界を参照します。比較評価には、主張の支持・反証・境界と、必要な調査側の解釈を使います。研究紹介専用の新しい属性や、問い・方法・図・結果・評価を毎ページに再入力する台帳は追加しません。見た目が似た原図でも、課題・データ・尺度・条件が異なる結果を比較する場合は、その違いを保持し、優劣の主張を比較可能な範囲へ限定します。

### 定量的な根拠・主張だけに用いる属性

```text
numeric, numerator, denominator, unit, aggregation_level, uncertainty
```

定量的な場合は、解釈に必要な単位・尺度、集計水準、不確実性を保持し、重複、欠測、時間範囲、統合値かどうかを示します。分子・分母は、比率・割合・率など、その意味を説明するために必要な場合の条件付き項目です。単独の平均や係数などのために分子・分母を作りません。元資料の標本数などが解釈を変える場合は、比率の分母とは別の情報として、標本・方法・条件の記述から確認できるようにします。

差や関連が確認されなかったことだけで、効果や関係の不存在が証明されたとは扱いません。定性的・概念的・法的な資料では `numeric: no` または `not applicable` と記載でき、分母を作りません。

## 根拠・判断・情報状態

情報源の主張を確認したことと、その主張を調査の回答として採用したことを区別します。採用根拠は `evidence` と `locator`、調査側の橋渡しは `manager_interpretation`、概念の分け方を選んだ理由はこのモデル定義に置きます。RRMのうち主張の意味や強さを変える関係を、これらの既存記録から復元できるようにします。

情報がない場合は、必要に応じて次の意味を既存の説明欄・限界・不確実性へ記載します。この区別のために新しい状態項目や列を必須化しません。

| 情報状態 | 記載時に区別する意味 |
|---|---|
| 未確認 | 必要な報告・箇所をまだ調べていません。 |
| 不明 | 確認した範囲でも確定できません。`unclear` などを用い、確認範囲を添えます。 |
| 該当外 | 項目が対象に適用されません。`not applicable` と、対象との関係を示します。 |
| 否定 | 情報源が存在・成立を否定しています。調査で見つからなかっただけの場合と区別します。 |
| 競合 | 同じ対象・時点・基準について両立しない報告があります。双方の根拠を残します。 |

`not reported`（報告なし）、`not measured`（測定なし）、`not pooled`（統合なし）、`inaccessible`（アクセス不可）は相互に置き換えません。必要性がない `not needed` と、必要だが得られていない値も区別します。

## 能力質問と境界例

次の問いは、このモデルが表現すべき能力を点検するためのものです。個別記録を作る際の新しい必須項目ではありません。

| 能力質問（CQ） | 回答の形と確認先 | 保留する条件 |
|---|---|---|
| 同じ研究の複数報告を識別し、使用した版と箇所を示せますか。 | `work_id`、`reports[]`、情報源の版、根拠の `source_ids[]` と `locator` | 研究の同一性や使用版が未確認です。 |
| 中心的な主張の支持・反証・境界へ戻れますか。 | 主張から根拠、研究、報告へたどり、反証と境界を併記します。 | 関係する出典や意味を変える条件が欠けています。 |
| 情報源の結果と調査側の解釈を区別できますか。 | `result_or_argument` と `manager_interpretation`、必要時の `claim_role` を照合します。 | 解釈を支える観察・橋渡し・限界を確認できません。 |
| 定量値の意味と情報不足の理由を説明できますか。 | 条件付き数値属性、時間範囲、限界・不確実性を確認します。 | 分母・比較条件等が不明で、主張の強さを判断できません。 |
| 中核研究の要約・図・評価から、方法と結果とその限界を説明できますか。 | 研究の対象・方法、根拠の条件・結果・所在、主張の支持・境界、プロットと図契約を参照します。 | 原図の意味、比較条件、評価の橋渡しが未確認、または読者向け説明に必要な内容がありません。 |

以下は定義の境界を確かめる仮想例です。実際の研究結果を主張する例ではありません。

- 研究Aのプレプリントと雑誌論文が同じ実験を報告する場合、情報源は分け、確認済みの同じ `work_id` に結びます。研究件数は一件とし、抽出値が改訂されていれば使用版を残します。
- ある表の数値が複数の報告に再掲される場合、再掲の出典は保持しますが、独立した実験結果として支持を増やしません。方法・対象が異なる追加実験なら、その違いを確かめて研究単位を判断します。
- 同じ結果から「条件CでXが観察された」と「別の場面でもXを期待できる」を書く場合、後者の橋渡しと転用条件は調査側の解釈です。測定の記載が見つからない状態を「Xは成立しない」という否定へ変えません。

## 統合前の追跡確認と改訂

統合前には、採用した報告が研究・論証または明示した非研究資料に対応すること、根拠から出典箇所へ戻れること、中心的な主張に支持と必要な反証探索があることを確認します。定量的な場合は、その量に適用される数値属性を確認します。読者向けの表現が根拠と境界より強くならず、解釈が識別できることも確認してください。

情報を追加すればCQに答えられる場合は収集へ戻ります。単位・同一性・関係の定義を変える必要がある場合はモデル改訂として扱い、影響する既存記録と比較を確認します。保護する区別は、報告と研究、結果と解釈、論理形式と責任、支持と反証です。

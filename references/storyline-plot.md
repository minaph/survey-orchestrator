# ストーリーライン・プロットのモデルと運用

プロット（`storyline_plot`）は、読者に答える問い、根拠、図の関係、結論の境界、次の問いをまとめる作業モデルです。G0から作り、検索・読解・図の選択・統合・資料制作で得た内容に応じて改訂します。構成を制作前に検討し、完成資料の問題を根拠まで遡って修正するために使います。

## 目的と記述の分担

対象読者、中心となる問い、暫定回答が定まったら作成します。一つのコンテキストで改訂でき、後続の制作で構成を補作せずに済む程度の具体性を保ちます。資料台帳・監査履歴・完成成果物との役割を分けます。

| 記述 | 保存する内容 | 利用目的 |
|---|---|---|
| プロット | 問いと回答、根拠の置き場、図で示す関係、境界、次の問い | 構成の設計と修正 |
| 読者向け資料 | 主張、方法、図、比較、留保、出典、結論 | 読者の理解と判断 |
| 監査記録 | 出典・主張のID、所在、検索判断、ハッシュ、状態、レビュー、制作計測 | 来歴と検証の追跡 |

プロットから監査記録へ参照できます。読者向けスライドには、意味を説明しないID、担当者の役割、ハッシュ、検索計測、レビュー指示を持ち込みません。「未測定」「出典へのアクセス待ち」など、主張の意味を変える留保は読者に示します。

[研究者の読解モデル（RRM）](rrm.md)は各行の意味を検討する参照モデルです。現在の回答を変え得る対象・操作・結果などの関係を取り出すために使い、行種別・得点・追加の並び順にはしません。参考にしたPDFや発表資料の構成上の観察と、分野の情報源から抽出した主張は、[参考物分析](reference-analysis.md)に沿って分けます。

## 階層と対象単位

プロットは次の四層を扱います。各層には問い、回答、後続へのつながりがあります。

| 層 | 一件として扱う単位 | 上下の関係 |
|---|---|---|
| 資料全体 | 中心質問、中心回答、最終統合を持つ資料 | 節の回答を統合します |
| 節 | 一つの下位質問と局所回答 | 根拠ブロックを束ね、次節へつなぎます |
| 根拠ブロック | 一つの問いに答える研究詳説、比較、機序、境界、統合操作 | 一つ以上の研究・根拠・図を束ね、必要な説明をスライドへ配分します |
| スライド | 一つの読者質問と説明上の役割 | 一つの認知的な作業を担います |

スライド行では、次の関係を追えるようにします。見出しと本文だけで回答を閉じず、根拠の境界と次の問いをつなぎます。

| キー | 意味と確認する問い |
|---|---|
| `T` | 見出し・質問。読者はここで何を知る必要がありますか |
| `B` | 方法・結果・比較・説明。何を行い、観察し、推論しましたか |
| `Bottom` | 境界を付した要点・橋渡し。根拠を踏まえて何が答えられますか |
| `Figure` | 図で確かめる関係と具体的観察。本文だけでは確認できない何を示しますか |
| `Next` | この回答から生じる次の問い。なぜ続くのですか |

一枚の役割は読者が行う理解・比較・評価の単位です。論文、抽出根拠、図、ページの数は一致しません。一つの研究を複数ページで詳説しても研究は増えず、一つの比較ページに複数研究の原図を載せても研究を一件へ統合しません。`Figure`にはページ内の図が共同で確かめる関係を記し、個々の図の来歴は既存の図参照から辿ります。ページへ複数図を載せる場合も、図ごとの契約とページ対応を保持してください。

根拠ブロックでは、中核研究が何を問い、どの対象・条件で、どの方法を用い、実際の図表にどの結果が現れ、何と比べてどこまで評価できるかを説明します。概要は採用理由を短く示せますが、研究詳説を一言の評価や論文名だけで終えません。必要な情報は`B`、`Figure`、`Bottom`、根拠・主張への参照へ配分し、各ページに同じ説明や新しい必須欄を複写しません。

HCIの実証文献では、対象・標本・課題・操作・比較・測定概念を示す研究カード、報告結果・差や関連が確認されなかった結果（null）・分布・効果を示す根拠表示、未測定事項・標本や課題の限界・転用条件・次の検証を示す境界カードが診断に役立ちます。同じ区別と順序を保持できれば圧縮できます。全分野に三ページ構成を要求するものではありません。

## 記録形式と同一性

モデル定義は上の単位と関係を定め、個別のプロット行には対象の質問・回答・参照を記述します。次の一覧は適用条件に応じて使う論理属性で、常時全欄を埋めるフォームではありません。中心の問いや節の接続を説明する属性と、制作・検査用に展開する属性を区別します。Markdownは人が改訂するノートに、TSV/CSV/JSONLは行単位の記録に向きます。任意のMarkdownはチェッカーの解釈対象外です。発表資料のG5/G6で厳格な事前検査を行う場合は、次のJSON包絡形式へ変換するか、先頭行に`plot_version`、`plot_scope`、`plot_status`を宣言したTSV/CSV/JSONLを使います。

```text
plot_version, plot_scope, plot_status, audience, central_question, central_takeaway, review_concept
plot_row_id, section_id, section_question, section_answer, transition_question
section_purpose (narrative_jobでは不足する場合のみ)
slide_id, evidence_block_id
T, B, Bottom, Figure, Next
narrative_job, presenter_note
claim_refs[], source_refs[], visual_ids[], source_state, boundary, uncertainty
figure_relation, rrm_focus (任意)
unresolved_question, next_research_action
```

同じ主張・境界を複数行で使う場合は、[主張と根拠の記録](evidence-model.md)を正本とし、`claim_refs`等で参照します。節の`section_answer`、行の`B`・`Bottom`・`boundary`に同じ内容を手動で複製しません。節での統合、行固有の適用範囲、読者への言い換えなど、意味や用途が異なる部分だけ別に記述します。出典・主張と同じ`source_state`・`uncertainty`も参照先から取得できます。共通の根拠が改訂されたら、影響する見出し・本文・図指定・結論と、検査用の展開値を更新します。制作メモの現行判断や残件も合わせ、変更前の記述は履歴として区別します。これにより、後続担当者は現在採用する根拠と判断を辿れます。

図の`source_visual_route`・`visual_candidate`・`reader_role`は[図の取得記録](figure-extraction.md)や[視覚契約](evidence-visual-contract.md)、スライドの`evidence_class`は[制作マニフェスト](presentation-build-contract.md)から参照できます。同じ内容をプロットの独立した判断欄にはしません。図の役割と異なる行固有の説明上の役割は`narrative_job`に残します。制作前にプロットで決めた内容を正本へ引き渡した後も、検索や閲覧に必要なら既存キー名による派生表示として取り出せます。現行のプロットチェッカーはこの四属性を要求・照合しません。図契約とマニフェストで必要な項目は、それぞれの契約に従って展開します。

`transfer_note`は他の属性と異なる役割や実参照が定められていないため、新規プロットの標準属性から外します。既存の値は、研究結果の転用可能性なら根拠の`transferability`、主張が成立する条件なら主張の`boundary_conditions`、特定行だけの読者への適用説明ならその行の`boundary`や本文へ統合します。内容を確認し、判断理由や独自の留保を失わずに移します。旧名を互換上読み込む場合も、第二の編集対象として残しません。

`plot_row_id`は改訂を通じて同じ行の識別子として保持します。`slide_id`は後で付けるため、G0ではnullにできます。`figure_relation`は`Figure`に対応する既存の直列化キーで、独立した第二の関係として記述しません。`rrm_focus`は、検索・修正・読者向け説明・レビューに役立つ場合だけ主要なRRMの動きを示します。既存の参照で関係を辿れる場合は不要です。本文と図の役割分担は既存の変更記録や制作メモに記載でき、共通の`text_job`・`visual_job`欄は追加しません。次は根拠が未確認の初期行の例です。

```json
{
  "plot_version": "v0.1",
  "plot_scope": "target_survey",
  "plot_status": "draft",
  "rows": [
    {
      "plot_row_id": "P-01",
      "section_id": "SEC-01",
      "evidence_block_id": "EB-01",
      "slide_id": null,
      "T": "読者が判断する課題は何ですか",
      "B": "暫定的な枠組みです。根拠の確認は未了です。",
      "Bottom": "作業上の回答であり、裏付けられた結論ではありません。",
      "Figure": "必要な関係を確認するまで図を置きません。",
      "Next": "どの出典や比較でこの枠組みを検証できますか",
      "claim_refs": [],
      "source_refs": [],
      "visual_ids": []
    }
  ]
}
```

現行のプロットチェッカーは、包絡の版・範囲・状態、行の`plot_row_id`・`section_id`・`evidence_block_id`を確認します。厳格な検査では`plot_status=verified`または`synthesis`とし、`T`・`B`・`Bottom`・`Figure`・`Next`（対応する別名も可）の空でない値が必要です。参照先の文章からこれらを展開・生成してから検査へ渡し、参照だけを置いて読者が読める本文を省きません。チェッカー自体は参照先の文章を取得しません。

マニフェストも渡す厳格な検査では、版・節・根拠ブロック・スライドの対応と、宣言された主張・情報源・図の参照網羅を確認します。参照の連鎖は`plot_row_id -> evidence_block_id -> claim/source refs -> visual_id -> slide_id`です。スクリプトが確認するのは存在・同一性・網羅範囲で、質問や図の関係の妥当性はレビューで判断します。スライドを制作しない文章サーベイでは、必要な問い・回答・境界をMarkdown等で記述でき、発表用のIDや図属性を埋めるためだけの記録を作りません。

作業状態には必要に応じて`idea`、`searching`、`evidence_pending`、`draft`、`verified`、`blocked`、`deferred`、`synthesis`を使います。読者向けの品質得点ではありません。所在や機械検査に用いる監査項目は台帳・付随記録へ置き、プロット自体の可読性を保ちます。参考物のプロットは`plot_scope=reference_artifact`とし、対象サーベイの主張台帳へ暗黙に結合しません。

## 段階ごとの利用

### G0：疎な初期プロットを作る

読者と用途、中心質問と暫定回答、節の質問と順序、各節の予想回答を一つか二つ、必要な根拠・方法、次の調査や設計判断、暫定回答を変えそうなRRMの関係を書きます。未確認事項を明示し、数値・精密な出典主張・完成時のページ数を補作しません。

### G1–G2：調査の問いを更新する

参考物の読解と調査手順の確定に合わせて節の問いを改訂します。検索はプロットの不足へ答えるために行います。対象、操作、比較、結果、境界、統合の関係に加え、機序、競合説明、境界例、転用条件、視覚的関係の不足を探します。枝を追加・削除・保留した理由を残し、説得的に見えるまで検索する口実にしません。

### G4：根拠ブロックを具体化する

題名・要旨・研究の主目的は関連性を見定める入口です。論文の役割や回答を決める際は、現在の問いを変え得る研究内の比較・反証・条件へ戻り、対象、操作、観察結果を確認します。一つの論文が背景と直接比較の両方を担うこともあります。確認した比較がどの回答を支持・限定するかに応じて採用することで、読者は研究の紹介から調査の判断へ進めます。

暫定回答を出典のある記述へ置き換えます。実証的・中心的、または意味を変える根拠ブロックで、`対象・母集団 -> 方法・根拠 -> 操作・比較 -> 結果・論証 -> 限界・境界`を辿れるようにします。出典が報告した結果、監督者の統合、設計上の推奨は文または欄を分けます。

差や関連が確認されなかった結果（null）、矛盾、アクセス不能、未検証の詳細を保持します。原典内で本文・表・図の値が一致しない場合は、各値の所在と集計範囲を確認し、確認できた対応と原因未確定の不一致を分けます。調査側の再計算は対象と計算方法を伴う独自の導出として示し、数値の一致だけで著者の集計方法を確定しません。異種指標を含む集約値は指標と集計範囲を保って説明します。中心ブロックでは意味や強さを変えるRRMの関係を確認しますが、六つの必須欄を追加しません。節の質問、`Bottom`、`Next`だけでは局所回答と移行の問いが分からない場合に明示します。

論文紹介の順序は、共通の問いに対する説明の進展から決めます。例えば、定義・設定を示し、方法と結果で一つの回答を支え、近接手法との違いを比較し、反証や未測定条件で回答を限定して、次の問いへ進めます。この順序は選択肢であり、研究ごとの固定ページ列ではありません。各研究を同じ長さで順に要約する構成では、どの研究が何を支え、どの比較が結論を変えるかを明確にしてください。

例えば架空の問い「説明を加えると理解は深まるか」では、同じ課題で説明あり・なしを比べた結果を選び、「直後の正答率は高いが、翌週の保持には差が確認されなかった」と観察を示します。「この課題では直後の成績に利点がある」という限定した判断へつなぐと、読者は説明の採用理由と、長期学習を別に検証する理由を理解できます。

### G4-V：出典側の図候補を対応づける

主張を担う図候補を`Figure`へ対応づけます。方法図では設定・条件、結果図では方向・分布・比較・不確実性、境界図では不足や限界、統合候補では比較軸と推論範囲を確認します。出典自身のラベル、軸、凡例、注記、キャプション、クレジットが何を示すかを記録します。

詳細プロットを制作へ渡すまでに、中心結論を支える比較の対象・操作・観察と、それを示す図・必要なパネルの対応を確定します。図番号や候補名に加え、内容と条件を確認して`B`・`Figure`・`Bottom`をつなぎ、制作担当者が根拠を選び直さずに実装できるようにします。方式の手順を示す図と性能などの結果図、原図と説明用の再構成は、実際の内容と来歴から区別します。再構成の使用可否は下記の既存契約に従います。確認範囲は主張への影響に合わせ、補助図の切り出し・配置などの制作判断は残せます。

中核研究では、方法・構造と結果、異なる条件、競合手法、失敗例など、説明に必要な原図を組み合わせて候補を探します。一つの代表図だけで回答できる場合は増やしません。複数論文の原図を比較のために並置することと、それらを改変して一つの独自図を作ることを区別し、それぞれの図から出典箇所・研究・帰属へ戻れるようにします。異なる課題・データ・尺度・条件の結果は差を明示し、見た目や数値だけで優劣を断定しません。

候補の選択には[図抽出](figure-extraction.md)を、再構成・サーベイ独自の統合の候補には[再構成レビュー](reconstruction-review.md)を適用します。出典経路・出典との対応はG4-V、`reader_visual_job`と`reader_layout_route`は埋め込まれたG4-PDの記録、プロットと主張の採否はG4-Pが扱います。この段階で読者向けの役割、reader/dense/splitの経路、本文と図を別々に読む検査を先取りしません。候補が魅力的という理由だけで有用とは判断しません。

図の種類と出典経路は分けます。原図、忠実な再構成図、情報源間の比較、サーベイによる説明・統合図、境界・不確実性表示の区別をレビュー資料に残し、読者に必要な帰属をスライドへ示します。経路、実際のスライド役割、出典資料、キャプション、要素対応表の要件は[再構成レビュー](reconstruction-review.md)を正本とします。

### G5：制作可能な行へ展開する

必要なスライド行について、見出し、本文、要点、図の関係、出典の役割、留保、移行、短い発表者メモまたは`not_needed`を具体化します。概要・橋渡し・研究詳説・横断比較・評価と統合の役割に応じた密度は[デザイン分析](survey-design-analysis.md#役割に応じて説明の密度を決める)を参照します。この版からスライドマニフェストと視覚契約を導きます。表紙・参考文献・移行・付録は根拠欄を`not_applicable`にできますが、読者の位置づけや接続に関わる役割を記述します。

### G6：完成資料から問題を遡る

プロットとレンダリング済み資料を先に渡し、[レビュー基準](review-rubric.md)と[視覚レビュー](visual-review.md)で検討します。問題は`読者の混乱 -> スライドの役割・図の関係 -> 根拠ブロック -> 節の問い -> 中心プロット`の順で遡ります。表示だけに問題があれば資料を、推論の飛躍があれば根拠または主張範囲を修正します。最初に影響する行へ戻り、監査注記や本文の追加で構成上の欠陥を覆いません。

## G4-Pの形成的レビュー

### 適用条件と入力

主張を含むサーベイ発表資料が、最初のG4-V候補選別を終えてG5の制作へ進める段階で行います。中心質問、節の順序、主要主張、図の経路が大きく変わった場合も再適用します。表紙のみ・図を扱わないレビューには適用しません。既存段階間の形成的な引き渡し確認で、独立したライフサイクル状態や正式な公開ゲートではありません。

短いレビュー趣旨と現在のプロットを先に渡し、文献と主張の根拠、図候補と出典切り抜き、既存契約と監査資料の順に示します。趣旨には、誰の理解・判断を変えるか、問い、研究の束ね方、現在支持できる回答と境界、実施可能な範囲を書きます。約400字は起草の目安で、固定長・検査規則・スライド要件ではありません。`central_question`と`central_takeaway`を更新し、重複する結論欄を増やしません。

### 四つの確認領域

1. **メッセージと構成：** 中心質問と暫定回答、現在位置、節の回答の蓄積、最終統合、次の問いや節への再入場の理由を読み取れますか。
2. **文献選択：** 主張に対する採用理由、より適切な候補、反証、境界例、方法の差、次の検索、未検索・未測定・未報告を検討していますか。
3. **主張と図の関係：** プロットの関係を図が示し、本文と図の役割が区別できますか。本文を除いて図内のラベル・軸・凡例・注記・キャプション・クレジットを残したとき何を観察できるか、図を除いたとき本文が留保込みで何を主張するかを確かめます。グラフは軸、単位、比較対象、ラベル、凡例、集約、不確実性、境界を確認します。中核研究の説明に必要な原図を選び、複数図の共同の役割と各図の出典を確認します。
4. **情報量と発表の接続：** 各計画スライドが一つの作業を担い、`T -> B -> Bottom -> Figure -> Next`を形成していますか。その問いを答えるための条件・方法・結果・評価が不足していませんか。比較を同時に見る必要と可読性を検討し、内容を維持した配置・拡大・連携する詳細ページを選びます。短い発表者メモで注目箇所、推論してはいけない範囲、次の問いへの接続を示します。不要なら`not_needed`とし、完全な台本は要求しません。

採用した各文献に、何か、重要性・新規性、方法の要点、検証方法、議論・限界・反証、次の読解・検索判断の六問を分析の観点として適用します。出典の役割・主張リスク・資料種別に応じて深さを変え、全論文に同じ量の回答を作りません。次の行動は`next_research_action`でブロック・節ごとに共有でき、各論文に次の論文を一件ずつ割り当てる必要はありません。

中心経路を十分に検討し、図の意味と本文との役割分担は全計画スライドで確認します。G6の母集団と通常行の事前抽出は[レビュー基準](review-rubric.md#レビュー資料と検査母集団)に従います。本文の言い換えだけの図は、根拠・比較・留保の不足を先に点検し、必要な実図や説明を補って役割を明確にします。問いへ寄与しない図は削除・保留・再分類できます。説明・根拠・統合の役割が残る図を、ラベル変更だけで検査対象から外しません。

### 判定と戻り先

引き渡し判定には`go`、`revise`、`narrow`、`stop`を使います。順に制作準備完了、最初の影響行への差し戻し、主張・根拠・図・転用範囲の縮小、有意味なサーベイを支えられない状態を表します。`search_more`、`restructure`は`revise`に伴う具体的な修正行動で、状態値を増やしません。

既存の変更記録に、`plot_version`、範囲と網羅状況、独立した`g4p_verdict`、行・図ごとの指摘と理由、`strong`/`adequate`/`fragile`/`blocked`の評価、修正、再確認条件、G4またはG4-Vの戻り先を残します。正式なG5/G6の`plot_review.status`は`passed`/`pending`/`blocked`であり、`g4p_verdict`と混用しません。

改訂後は影響した根拠・図のみ再検討します。中心質問、節の累積関係、中心的な主張と図、根拠の十分性を局所修正できない場合に全体を再構成します。`go`はG5・出典忠実性・G6の合格を意味しません。発表者メモの有用性はここで意味的に確認し、条件付きのプロジェクト契約がない限り、その欠如を機械検査による公開不合格に変えません。

## 参考物への適用と改訂

複数の資料が与えられた場合は、必要に応じて参考物自身の構成と対象サーベイの構成を分けてプロット化します。分野地図、進行、局所反復、ナビゲーション、図の役割、出典、締めくくりの統合を比較します。論文の論証、レビュー報告の根拠不足、発表の診断にも使えますが、どの資料を対象とするかを明記します。

初期は疎に書き、根拠の検証に応じて具体化します。中心の問いを軸にしつつ、根拠が変われば節順・回答も改訂します。未解決行を流暢な文章で埋めず、検索・抽出・比較・再構成・図の保留を判断するために使います。短い変更注記や版差分を残し、過程の日誌を際限なく追記しません。

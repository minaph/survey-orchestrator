# 調査の管理と委任

本書は、明示的な委任、受け渡し、進行判断が役立つ調査で使います。管理上の記録は監査側に置き、分野の根拠として引用しません。G0–G6の順序と状態責任は [SKILL.md](../SKILL.md#工程と状態責任)、意味の関係は [rrm.md](rrm.md) を参照してください。

## 担当と責任

| 担当 | 責任の範囲 |
|---|---|
| 管理者 | 問い、プロットの初期案と改訂、計画、範囲変更、情報源の採用、構成概念の定義、統合、矛盾の解決、物語、最終判断 |
| 作業担当者 | 指定した範囲の作業と、合意した形式による出典を伴う結果の返却 |
| 専門担当者 | 方法、分野、統計、情報源の品質に関する助言 |
| 検証担当者 | 成果物や主張の独立した確認。修復は実装側へ返します。 |

成果物ごとに責任者を一人定めます。複雑な案件ではWBSやRACIを使えますが、担当を明確にする任意の道具として扱い、読者向けの内容や追加成果物の理由にはしません。

## 分解と実行方法

管理者または決定論的なスクリプトから始め、作業が自己完結し、隠れた文脈なしに結果を確認できる場合に委任します。分解の粒度は、あり得る解釈・分岐の多さ、独立検証の費用、情報源のアクセス・形式・同一性・抽出リスク、共有用語を変えずに並行できるかで判断します。これらは定性的な目安であり、数値得点や必須の判断表にしません。

| 作業 | 適する実行方法の例 |
|---|---|
| DOIの正規化、重複検出 | 決定論的なスクリプト |
| 多数の単純なメタデータ行 | 一括抽出 |
| 採用済み・アクセス可能な情報源の図表候補の確認 | 一括処理、または範囲を定めた情報源担当者 |
| 独立した候補検索 | 並行する作業担当者 |
| 難解または長大な情報源 | 情報源単位の担当者 |
| 矛盾の解決、定義、統合 | 管理者 |
| 影響の大きい中心的な主張 | 対象を絞った独立検証 |

共有スキーマは小さくし、並行作業前に用語を確定します。論文ごとに担当者を置くことを既定にせず、品質、待ち時間、検証の改善が説明できる場合に分けます。

## 作業依頼の契約

次のテンプレートで、入力、所有範囲、出力、終了条件を渡します。ラベルは依頼文のための自然言語であり、機械スキーマの変更ではありません。

```text
作業: 範囲を定めた一つの問い、情報源、または成果物
入力: 正確なファイル・URL、検索式、日付範囲、スキーマ、担当する
plot_row_ids/evidence_block_ids、解消するRRM上の不足
制約: 情報源の品質、除外条件、単位、裏づけのない推論の禁止。
必要な橋渡しは調査側の解釈として識別する
出力: source/work/evidenceの記録、出典箇所、不確実性。
発表資料では、中核研究の問い・条件・方法・結果・比較評価・限界を
説明する既存記録への参照と、必要な原図候補の切り抜き・来歴。
複数図はそれぞれの役割と出典を識別し、候補なし・アクセス不可は
明示する。プロットの変更は担当行に限定する
終了: 合意した受入確認と件数の確認を満たす
管理者へ返す事項: 曖昧さ、アクセス不能、矛盾、範囲の問題
```

担当者が意味を変え得る対象・操作・結果・境界を確認できるよう、RRMの必要な文脈を渡します。六観点をすべて記入する台帳は要求しません。結果と解釈の区別は根拠モデル、解釈の条件はRRMを使います。

担当者は範囲を黙って変えたり、異なる構成概念を統合したり、因果を推論したり、推奨へ進めたりしません。矛盾や範囲の問題が見つかったら、根拠、不確実性、管理者が選べる少なくとも一つの限定的な対応案を返します。

## 受け渡しで確認する材料

工程の順序はSKILL.mdに従い、各受け渡しでは次の判断に必要な材料を確認します。

| 判断対象 | 最小の受け渡し材料 |
|---|---|
| 問いの有用性と実行可能性 | 読者、成果、範囲、問い、初期プロット |
| 検索で主張できる範囲 | レビュー方法、網羅性、採否条件、検索案、プロットの問いと不明点 |
| 抽出を拡大できるか | 既知の文献の回収、コードブック、版の規則 |
| 根拠の追跡可能性 | 報告・研究・根拠・主張のリンク、不足 |
| 原図を設計前に確認したか | 採用候補の切り抜き・来歴、または候補なし・アクセス不可の記録、出典箇所、経路、理由 |
| 統合が境界と物語を尊重するか | 反証、不確実性、解釈、現行プロット |
| 成果物が使え、物語が完成しているか | プロットから導いたマニフェスト、採用図の参照、出典表示、表示結果 |
| 不確実性や阻害事項が残るか | 物語の指摘、実物の検査、警告、標本レビュー、正式なレビュー記録 |

根拠の受け渡しでは、重要なRRMの関係を復元でき、結果・解釈・推奨を区別できるかを確認します。中核研究を要旨と一枚の代表図だけで完了扱いにせず、担当する問いへの回答と評価に必要な方法・実図・結果・留保が揃ったかを確認します。図の受け渡しでは、G4-Vの情報源側の候補・来歴と、G4-P内のG4-PDの読者向け設計を区別し、複数図は図ごとの契約とページ対応を保持します。詳細な採用・比較条件は図の定義元を使います。

各受け渡しで `go`（進行）、`revise`（修正）、`narrow`（範囲縮小）、`stop`（停止）を選びます。確認に失敗した場合は最初に影響を受ける工程へ戻し、既存の変更記録に残します。この進行判断を、正式な検査・レビューの合否状態へ直接写しません。

## 独立検証

主張が中心的、情報源の解釈が難しい、成果物の影響が大きい、見逃しの費用が大きい場合に独立検証を使います。全面的な二重作業が見合わない場合は、中心的・数値的な主張、境界事例、事前に定めた通常行の無作為標本を確認します。

検証担当者には現行プロット、成果物、基準を渡し、管理者の望む結論や診断を渡しません。監査情報を見せる前に、読者向けの物語を質的に読んでもらいます。必要な場合は学術的評価・情報源への忠実性、表示・投影、総合判断を分け、阻害事項を平均点で相殺しません。

モデル選択、対比較、盲検資料、反復的な校正はタスク固有の選択肢です。WBS、RACI、担当者ID、ハッシュ、レビュー状態、制作記録は監査側に保持し、分野の参考文献件数や読者向けの内容へ含めません。

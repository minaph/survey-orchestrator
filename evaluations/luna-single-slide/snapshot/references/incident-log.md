# 一般化した失敗パターン

本書は、再利用できる失敗パターンと対応する予防策をまとめます。個別ラウンドの報告、ページ番号、レビュアーID、ハッシュはプロジェクトの監査資料に置きます。同じ問題が再発した場合は既存の定義・手順・検査を改善し、類似の経緯を追記しません。

| 失敗パターン | 予防策・戻り先 |
|---|---|
| 根拠を示す資料がカードと数値だけで構成される | 制作前にマニフェスト、実際に確認できる根拠の表現、タスクに即した意味のある図の必要量を定めます。[presentation-build-contract.md](presentation-build-contract.md) を参照します。 |
| 図の設計が先行し、原図の抽出機能を使わない | マニフェスト作成前にG4-Vを実施し、対象となる主要な情報源を確認します。採用候補の切り抜きを保持し、原図を基本とします。再構成は許可された理由と読者向けの出典注記を伴わせます。[figure-extraction.md](figure-extraction.md)、[reconstruction-review.md](reconstruction-review.md) を参照します。 |
| 強調色が分類・状態・装飾を兼ね、意味が混ざる | トークン表で役割を定め、文字色の役割と強調色を使うページの割合を確認します。参照プロファイルの値を普遍的な基準にしません。 |
| 未確認の衝突や文字切れが残る | 全ページの境界ボックス・はみ出し検査を行い、警告ページを確認します。手作業で選んだ高リスクページだけに依存しません。[visual-review.md](visual-review.md) を参照します。 |
| 監査用の語彙が読者向けの本文へ漏れる | 管理情報は監査側で扱い、スライドのXML・抽出テキストで内部トークンの混入を確認します。 |
| 作業指針を分野の根拠として示す | 情報源の役割を区別し、作業方法の参考資料を分野の文献件数へ含めません。[evidence-model.md](evidence-model.md) を参照します。 |
| 出力変換で日本語の語句・字形が壊れる | 保護する用語、改行、フォントの変換往復、検索可能な補助資料を確認します。文字抽出に加えて字形を観察します。 |
| メタデータが整う一方、根拠が乏しい | 根拠の充足、投影時の可読性、可搬性を相互に相殺できない合否条件として扱います。[review-rubric.md](review-rubric.md) を参照します。 |
| ラウンド履歴の追記でスキルが肥大化する | 不具合を一つの一般的な規則・検査へ整理し、個別の経緯を監査資料へ移します。 |

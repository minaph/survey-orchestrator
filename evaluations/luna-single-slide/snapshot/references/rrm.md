# 研究者の読解モデル（RRM）

## 目的と位置づけ

Researcher Reading Model（RRM）は、情報源を読んで文献調査の主張へつなぐ際に、保持すべき意味の関係を整理するモデルです。読解、根拠抽出、主張、ストーリーライン・プロット、図の選択、読者向け表現に共通の観点を与えます。本書は六つの観点、必要な関係を復元できる条件、調査側の解釈の条件を定義します。

これは本スキルの作業上のモデルです。研究者の認知過程を実証した心理学的法則ではなく、六項目の必須フォーム、得点、独立した工程、章やスライドの順序も定めません。プロットの六つの文献質問は分析の問い、[根拠モデル](evidence-model.md) は対象と関係、[ストーリーライン・プロット](storyline-plot.md) は物語の記録を定め、RRMはそれらにまたがる意味を点検します。

## 六つの読解観点

一つの観点は、情報源と調査上の判断の間で確かめる意味の関係です。観点の名前は機械識別子として保持します。一つの根拠や図が複数の観点に関わるため、ページ・質問・担当者との一対一対応は想定しません。

| 観点 | 問いと確認対象 | 既存の記録先 | 読者向け表現の例 |
|---|---|---|---|
| `positioning`（位置づけ） | なぜこの問題・研究・不足を取り上げるのか。問題、先行研究の不足、調査の問いを確認します。 | タスク設定、G0プロット、節 | 「この節では……を問います。」 |
| `identification`（対象の同定） | 何を誰について調べているのか。構成概念、単位、集団、コーパス、文脈、比較対象を確認します。 | 研究、根拠、主張 | 「ここでXは……を指します。」 |
| `operationalization`（操作化） | どのように観察可能にしたのか。設計、手順、測定、符号化、比較条件、時間を確認します。 | 研究の方法、根拠 | 「研究は……を測定・比較しています。」 |
| `result_inspection`（結果の確認） | 何が観察・論証されたのか。結果、推定、パターン、差や関連が確認されなかった結果（null）、図表と出典箇所を確認します。 | 根拠、原図と来歴を含む監査資料 | 「観察された関係は……です。」 |
| `validity_transfer`（妥当性と転用） | どこまで言えるのか。限界、不確実性、矛盾、未測定事項、転用条件を確認します。 | 根拠、主張、評価 | 「この結果だけでは……を示せません。」 |
| `synthesis_next`（統合と次の問い） | 調査として何を導き、何を次に問うのか。研究間の関係、慎重な解釈、残る問いを確認します。 | 主張、プロット、`Next` | 「この調査では……を支持する材料と解釈します。」 |

`rrm_focus` は、検索、修復、読者向け表現、レビューの判断に役立つ場合だけ、プロット行の主要観点として記載します。他の関係は既存の根拠・主張から追跡できればよく、全資料に六つの値を埋める必要はありません。

## リスクに比例した復元可能性

**リスクに比例した復元可能性（risk-proportional recoverability）** は、主張の意味や強さを変え得るRRMの関係を、紐づく既存記録から復元できることを求める方針です。中心的な主張では対象、操作、結果、境界を確認し、周辺的な資料では採用理由に必要な関係に絞ります。六観点の件数や充足率を測る方針ではありません。

例えば、測定法が違えば比較の意味が変わる主張では、`operationalization` を結果と結んで保持します。別集団への適用が問題となる主張では、`identification` と `validity_transfer` が必要です。情報が不足する場合は、[根拠モデルの情報状態](evidence-model.md#根拠判断情報状態)に沿って不足の理由を残し、推測で埋めません。

読者には、表示した主張を解釈するための対象・条件・結果・解釈・境界を示します。完全な出典、識別子、ハッシュ、制作記録は監査側に置きます。監査資料で詳細を復元できても、意味を変える分母・単位・比較条件・不確実性を読者から隠してよいことにはなりません。

中核研究の紹介では、問いと方法が結果の読み取りへつながり、実図のどこがその結果を支え、どの比較・留保から評価が導かれるかを説明します。一つの図を全観点の代わりにせず、方法図と結果図、異なる条件、反証などが必要なら組み合わせます。説明は一枚にも連続ページにも配分できます。六観点を各ページに複写することより、根拠ブロック内で読者が関係を理解できることを優先します。

### 推奨する読解の進め方

本スキルでは、まず題名・要旨・図表・結論・限界から調査との関連を見定め、その後、対象、方法、測定、比較、結果、図注へ戻って確かめる方法を推奨します。近接研究との比較で解釈や転用の疑問が生じたら、必要な箇所を再読します。

`関連性 → 対象 → 操作 → 観察された関係 → 境界 → 比較・統合` は作業の目安です。意外な結果は測定へ、境界の問題は対象集団へ、研究間のパターンは構成概念の違いへ戻る理由になります。これを固定の読解順序や発表順序にはせず、再確認に使う出典箇所と根拠のリンクを保持してください。

## 既存モデルと記録の対応

### プロットとの関係

`T → B → Bottom → Figure → Next` は読者向けの物語を記述する記法です。次の対応は、各要素が何を伝えるかを考える目安であり、全要素を毎ページに載せる規則ではありません。

| プロット要素 | 関係するRRMの観点 | 保持する意味 |
|---|---|---|
| `T` | `positioning`、`identification` | 問いと対象 |
| `B` | `operationalization`、`result_inspection` | 何を行い、何を観察できるか |
| `Bottom` | `validity_transfer` と調査側の解釈 | 何が導かれ、どこまで言えるか |
| `Figure` | 操作・結果・境界の確認 | 図が確認可能にする関係と出典箇所 |
| `Next` | `synthesis_next` | 次の問い・行動 |

プロットの所有責任、行の修復、`Figure` と既存の保存キー `figure_relation` の対応は [storyline-plot.md](storyline-plot.md) を参照してください。

### 根拠・主張・図の記録先

`source/report → work/study → evidence → claim → reader_wording` を保ちます。情報源の結果は `evidence.result_or_argument`、調査側の解釈は `claim.manager_interpretation`、読者向けの表現は `claim.reader_wording` に記録します。主張の論理形式と記述責任の区別は [evidence-model.md](evidence-model.md#主張) に従い、役割を論理形式へ混ぜる `survey_synthesis` などの値を追加しません。

図に関する担当範囲は次のように分かれます。識別子を共有しても、記録の責任は統合しません。

| 担当範囲 | 確認する関係 | 定義・手順の参照先 |
|---|---|---|
| G4-V | 情報源の図がどの関係を示す候補か。来歴と忠実性は確認できるか。 | [figure-extraction.md](figure-extraction.md)、[reconstruction-review.md](reconstruction-review.md) |
| G4-P | プロット・主張・RRM・候補図が、読者の理解につながるか。 | [storyline-plot.md](storyline-plot.md)、[review-rubric.md](review-rubric.md) |
| G4-P内のG4-PD | 採用する `reader_visual_job` と `reader_layout_route`、境界の見え方、理解の進展 | [presentation-build-contract.md](presentation-build-contract.md) |
| G5 | 主張の意味を保って読者向け成果物を制作する | [presentation-build-contract.md](presentation-build-contract.md) |
| G6 | レンダリングされた成果物で意味を確認できるか | [visual-review.md](visual-review.md)、[review-rubric.md](review-rubric.md) |

G4-PDはG4-P内の任意記録で、独立した工程や品質門ではありません。図の来歴を再収集したり、解釈・読者向け表現を複製したりする場所にもなりません。

## 調査側の解釈の条件

情報源が調査の問いに直接答えない場合、複数研究を関係づける場合、文脈をまたいで構成概念を読む場合、一般化や推奨に橋渡しが必要な場合には、調査側の解釈を行えます。その追加命題を、情報源の結果と区別して示します。

解釈が重要な場合は、次の順で説明します。

`情報源の観察 → 調査に残る問い → 一つの解釈 → 調査への寄与 → 境界・反証・確実性 → 読者向け表現`

| 条件 | 判断の基準 |
|---|---|
| 必要であること | 情報源と調査の問いの間にある、明示した不足を埋めます。 |
| 単純であること | 検討対象の命題を一つの明瞭で検証可能な命題として表せます。境界は別に見える形で保持します。 |
| 明確であること | 支持する、区別する、限定する、範囲を狭める、未解決のまま残す、などの判断を示します。 |
| 慎重であること | 定着した用語を適切に用い、構成概念、集団、比較条件、研究設計が支える範囲を越えません。 |

記録を増やす前に、以下の既存の所在へ置けるかを確認してください。

| 解釈の要素 | 記録先 |
|---|---|
| 情報源の観察 | 根拠の結果、`source_id`、`locator`、`work_id` |
| 調査に残る問い | プロットの未解決の問い、節の目的 |
| 一つの解釈 | 主張の `manager_interpretation` と `claim_role=survey_interpretation` |
| 調査への寄与 | プロットの回答、またはG4-PDで採用理由を述べる箇所。根拠そのものとして扱いません。 |
| 読者向け表現 | 主張の `reader_wording` と読者向け成果物 |
| 境界・反証 | 主張の境界条件、根拠の限界、`counterevidence_ids[]` |
| 確実性 | 主張の `certainty` と関連する評価 |

### 主語と述語を点検する

主語は情報源・研究、構成概念、操作、結果、境界、調査の主張などとし、「報告する」「測定する」「比較する」「含む」「除外する」「観察する」「推定する」「論じる」「限定する」「支持する」「区別する」「示唆する」「範囲を狭める」「示せない」「条件付きで転用できる」「未解決として残す」などの述語で関係を明確にします。

対象、条件・比較、出典箇所・境界を補い、「研究Aは条件CでXを報告していますが、Yを示すものではありません」のように書けるかを確認します。この語彙は明確さを点検する目安であり、分野固有の用語を禁止する閉じた列挙値ではありません。

観察から一般的効果、因果説明、規範的推奨、普遍的パターンへ移る場合は、橋渡しと境界を説明してください。`survey_value` に相当する採用理由は根拠へ数えません。解釈を単純かつ慎重に表せない場合は、主張を狭めるか、問いを未解決として残します。

## 読者向け表現と確認

中心的なスライドには主要な認知上の役割を一つ定め、題名と図からその役割が分かるようにします。この役割は一論文・一図の制限ではなく、同じ問いに答える複数研究・複数図を含められます。六観点の表を役割選択の参考にできますが、観点ごとにスライドを作る必要はありません。比較の同時性、説明の不足、可読性を検討して、G4-PDで `reader`（通常）、`dense`（密だが確認可能）、`split`（連携した分割）を選び、図の形式は別に選びます。

レイアウト前に、本文が述べる命題と、図が追加で確認可能にする関係を説明します。図が小さすぎる、切り抜きで条件が失われる、連続するページに新しい関係がない場合は、必要な研究情報を保って配置・拡大・連携する詳細ページを検討し、寄与しない要素を整理します。異なる課題・データ・尺度の結果を並べる場合は、比較可能な部分と条件差を示し、図の見た目だけで優劣を評価しません。具体的な本文・図の除去テストと合否基準は [review-rubric.md](review-rubric.md) を参照してください。

レビューでは、中心的・高リスクの主張について、対象・操作・結果・境界が復元できるか、結果と解釈が区別できるかを、読者向け成果物から監査資料の順に確認します。オブジェクト数、OCR、類似度、リンクの存在だけでは意味の保持を判定できません。決定論的検査と意味・表示・情報源への忠実性の評価は分けます。

モデルを拡張する際は、既存の情報源、根拠、主張、プロット、図の監査資料、レビュー記録で表現できるかを先に確認します。六観点を新しい台帳、必須フィールド、得点、合否状態へ変える追加は行いません。

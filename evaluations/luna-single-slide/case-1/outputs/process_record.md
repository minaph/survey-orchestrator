# 制作過程・検証記録

**対象**：3D表現を直接生成する研究動向を紹介・比較する、日本語・16:9・1枚のスライド  
**作成日**：2026-10-07（日本時間）  
**方法**：指定文献4件の範囲を定めた叙述的・横断比較。網羅的レビューや共通ベンチマーク比較は主張しない。

この記録は一時作業領域の消失後、残っていた固定版 `SKILL.md` と保存された依頼内容をもとに再作成した。以前の生成物を流用したのではなく、一次資料を取り直して各成果物を再生成した。

## 制作前の問いとプロット

- **読者の問い**：指定4研究は、3Dアセットの何を直接生成し、表現形式や出力の使い道をどう設計しているか。
- **仮の回答**：比較の軸は少なくとも二つある。Shap·EとStructured 3D Latentsは生成表現・デコード先の幅を示し、Hunyuan3D 2.0とSeed3D 1.0は幾何と外観の処理、または生成後の用途接続を前景化する。
- **持ち帰る主張**：指定研究では「3Dを生成する」処理の内部表現と、生成物の出口設計が異なる。これは設計焦点の整理であり、品質順位や時系列の因果的進歩ではない。
- **T → B → Bottom → Figure → Next**：何を生成しているか → 直接生成対象と出力先は研究ごとに異なる → 表現の選択幅と下流用途への接続を分けて読む → 原論文Figure 1の小抜粋4点と、出典報告を横並びにした独自の整理 → 共通条件での品質・使いやすさの比較は別途必要。
- **範囲**：依頼に列挙された4研究のみ。研究間で入力条件、課題、データ、評価指標が一致するとは仮定しない。

## 調査と根拠の確認

1. 作業ディレクトリの `SKILL.md` を読み、適用される参照契約を確認した。制作物・検索の監査と出典の扱いに関係する資料を参照した。
2. 指定4論文のarXiv一次資料ページを確認し、ネットワーク復旧後に各PDFを `audit/source_pdfs/` へ取得した。テキスト抽出で要旨、方法の概略、図番号と図注を照合した。
3. 図の出所を確認するため、該当PDFページを110 dpiで描画して `audit/figure_crops/page_*.png` に保存した。4点とも各論文のFigure 1から切り出した。原ページ画像、抽出PDF、切り抜き画像の対応は [sources_and_figures.md](sources_and_figures.md) に記録した。
4. 検討対象外の資料として指定された講義PDF・講義スライド、評価用の手本・対応表・比較資料、他ケースの作業環境・成果物は閲覧・探索に使っていない。

## 図の採否・読者向け設計

4枚の原図は、テキスト条件の生成例、複数出力形式と編集、形状・テクスチャ分担、シミュレーション場面という各論文の異なる役割を担う。スライドでは各図の直下に論文名、図番号、PDFページを置いた。図の配置だけで性能を比べたと誤解されないよう、下部に「設計焦点の整理」「課題・入力・評価条件が異なる」と明記した。

「表現の選択幅」と「生成後の接続先」は制作者が作った統合軸で、論文の著者分類ではない。パネル中の方法・出力の短文は各一次資料に基づく要約である。研究由来の切り抜き以外に、元論文の結果を描き直した図、数値の比較表、独自の性能スコアは作成していない。

## G4-P 相当の制作前確認

- **状態**：`go`。対象は予定している1枚のみ。
- **確認**：問い・主張・図の関係、各研究の要約がその研究の出力内容を超えていないか、同じ条件による優劣と誤読されないか、留保がスライド面にあるかを制作前に確認した。
- **修正**：共通の性能順位を避け、独自の横断軸であることと課題条件の不一致を図下に表示する。略語RFを避けてRadiance Fieldと記す。
- **終了条件**：4研究の各説明が原論文要旨・図注と対応し、図別の帰属がスライド上で見えること。

## 出力と表示検証

- 編集用の正本は `slide.svg`。レイアウト・文面は `build_slide.py` から再生成でき、4点の図版は `figures/` 内のPNGを参照する。
- 日本語フォントは `Hiragino Sans` を指定した。利用環境で日本語フォント描画を定める専用スキル文書を確認できなかったため、SVGから1920×1080 PNGを書き出す範囲に絞って試験し、PDFを再描画して字形を確認した。日本語、英数字、句読点、著者名、アラビア数字を目視し、欠字・豆腐・異体字置換を認めなかった。
- `slide.png`：PNG、1920×1080 px、16:9。4研究の図・方法・出力、見出し、出典行、注意書きを全体表示で確認した。文字切れ、要素の重なり、ページ外配置は認めなかった。
- `slide.pdf`：CoreGraphicsで1ページPDFを作成。ページ寸法960×540 pt（16:9）、PNG画像を144 ppi相当で配置。`pdfinfo` でページ数・寸法を確認し、PDFから1920×1080 PNGへ再描画してスライド表示を視認確認した。
- PDFは安定した表示を優先した画像ベースで、PDF内の文字検索・選択はできない。文字・レイアウト編集にはSVGを使用する。
- 初回の `rsvg-convert -f pdf` が不正なxrefを出したため、最終PDFには採用せず、PNGからCoreGraphicsで正常な1ページPDFを生成した。`cupsfilter` のSVG→PDF経路も出力を生成しなかった。
- `scripts/check_deck_quality.py` の診断も実行したが、正式な `visual_manifest.tsv` が未作成で、実行環境にPyMuPDF (`fitz`) がないため、チェッカーの判定は `fail`（PDF観測不能）となった。これはスライドの視覚品質を判定した結果ではない。代わりに `pdfinfo`、`pdftoppm` と実レンダリングの目視を行い、検査範囲と制限をこの記録へ残した。JSON結果は `audit/deck-check.json`。
- スライド投影機・他OS・他フォントへの移植、読者による理解度調査は未実施。

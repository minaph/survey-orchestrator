# 単一ページ制作の評価結果

## 結論

固定版スキルを使うLuna highの独立した3セッションで、日本語スライドを各1枚制作しました。出自を伏せた比較では、3件とも生成案を採用する判断になりました。これは、指定した範囲を一枚で説明する課題に対する定性的な結果です。原資料の講演全体より優れていることや、無人の本番運用で同じ品質が安定することを示す結果ではありません。

特に、図に現れる関係を本文で説明し、方法・出力・モデル差を具体化する点が評価されました。一方、機構を説明する図の選定、比較欄の意味の統一、見出しの主張範囲、図内の相対語、小字の可読性に改善点がありました。これらを最新版スキルへ反映しています。初回成果は書き換えず、改訂による性能改善は未測定として残します。

## 条件と比較手順

- 制作モデル：`gpt-6-luna`、reasoning effort `high`。`codex exec`を権限昇格で実行し、`--profile`は指定していません。
- 比較Reviewer：GPT-6.1 Sol / high。親の文脈を引き継がずに開始し、画像比較の判定保存までは出自・制作ログ・対応表を渡していません。
- 抽出：書誌を伴う研究紹介ページから、スキル内で具体的に分析・抜粋済みのページを除いた54ページが母集団です。シード`8817619230631463976`で非復元抽出した102・18・20ページを維持しました。
- 制作依頼：ページのスコープ・概略役割・論文書誌と共通の納品形式だけです。原資料の完成ページ、図の採用、要約・評価、文言、配置は提示していません。
- 使用版：52ファイルの固定版です。[ハッシュ一覧](snapshot-manifest.json)、[依頼文・実行情報](runs.json)、[抽出記録](sampling.json)を保存しています。
- 匿名化：両案を1600×900pxへ揃え、各組のA/Bを無作為に割り当てました。原資料のスライド番号だけをマスクし、本文・図・学術出典は保持しました。生成側は最終PDFを再描画し、PNGのメタデータを除きました。[対応と変換の記録](supervisor-mapping.json)を参照してください。

詳細な事前の判断基準は[評価プロトコル](protocol.md)にあります。制作途中の環境クラッシュとネットワーク補修を含む試行です。同じ会話と固定版から再開し、補修時も内容の助言は与えていません。復旧のない初回実行の所要時間・安定性を測る試験にはなっていません。

## 匿名比較の結果

以下は全3件の画像判定を保存してから対応表と突き合わせた結果です。Reviewerは原典の必要な本文・図を確認しています。原資料も単独ページとして評価しており、前後の講義内容による補完は評価対象外です。

| 課題と原資料頁 | 匿名の対応 | 判断 | 評価された点 | 生成案に残る改善点 |
|---|---|---|---|---|
| 3D表現を直接生成する研究の紹介・比較／p102 | A：生成、B：原資料 | A採用 | 4研究の出力・用途と横断的な説明がある | 「直接生成するもの」の欄に中間表現・モデル構成・最終出力が混在。生成例中心の図は機構説明が弱く、図の説明力では原資料が優位 |
| 明示的表現とニューラル陰関数モデルの関係／p18 | A：原資料、B：生成 | B採用 | 原図の分類境界を、座標・観測・占有確率・表面・メッシュ抽出へ結び付ける | 「出力せず」という見出しが最終出力まで否定するように読める。観測の例、略語MISE、Oursの指示先を明確にできる |
| 場による表面形状と代表モデルの位置付け／p20 | A：原資料、B：生成 | B採用 | 共通原理に加え、3モデルの場の値・用途を説明する | 小字の投影可読性、Oursの指示先、「形状を得る経路」という要点の具体性 |

比較の詳細と具体的な改善案は、[p102の匿名レビュー](blind-packets/pair-01/review.md)、[p18の匿名レビュー](blind-packets/pair-02/review.md)、[p20の匿名レビュー](blind-packets/pair-03/review.md)に保存しました。p20の初回レビュー時には原典取得ツールが内容を返さなかったため、その制限を記録し、公式PDFの取得・照合後の判断を追記しています。初回判定を後から消してはいません。

「原資料の説明が不足する」というReviewerの指摘は、今回渡した単独ページの役割に照らしたものです。原資料が次ページや口頭説明で補っている可能性を含め、講演全体の品質評価へ一般化しません。

## 制作過程から分かったこと

原典取得・切り抜き・生成・検査の実操作と、担当者が述べる読解・目視・採用理由を分けて確認しました。[制作過程の報告](recovery-process-report.md)には、イベントの該当行と保存ファイルを記載しています。

| 観点 | 確認できたこと | 確認の限界 |
|---|---|---|
| 自律的な調査と図選定 | ネットワーク補修後に各担当が原典を取得し、自ら原図へ方針を変えた。3件とも原論文図を使用 | 採用はFigure 1に集中し、他の図番号と十分に比較したかは裏付けが弱い |
| 要約と評価 | 最終本文と出典対応があり、匿名Reviewerが必要箇所を原文照合 | 最終文面の妥当性と、制作中に何度推敲したかは別。文言の変更前後を全件では復元できない |
| 実装とデザイン調整 | SVGまたはPPTXを実装し、PDF・PNGを生成。Case 2では文字サイズ拡大と再検査を直接確認 | 今回のJSONLでは`view_image`操作を確認できず、担当者自身の目視実施は自己申告。別のReviewerが最終画像を実際に確認したこととは区別 |
| 検証 | Case 2は依存不足を自力で解消し、PPTXの配置・構造検査を通過。全件でPDFの再描画等を実行 | Case 1の正式チェッカーはmanifest未指定・PyMuPDF未導入で未合格。3件全ての正式公開検査に合格したとは扱えない |
| 記録の信頼性 | ファイル・出典・完了イベント・ハッシュを保存 | Case 3の「参照Markdown未復元」は実際の52ファイル復元・ハッシュ一致と矛盾。本人の記録を保持し、監督側で訂正した |

初回の名前解決失敗時には独自模式図へ進む判断が見られました。アクセスが回復した後は原図が採用されており、初回の方針をスキルの効果だけへ帰属できません。途中の生成物が失われたため、環境補修前後の完成スライドを対比較した試験でもありません。

これらから、指定情報源に戻り、図を取得して一枚を完成させる自律性は確認できます。候補の意味を比較して最適な図を選ぶこと、文言を反復的に磨くこと、正式な検証を完了することの安定性は、今回の記録だけでは十分に立証できません。

全画像判定の保存後、同じReviewerへ出自と制作ログを開示して[制作過程の独立レビュー](process-review.md)を依頼しました。監督側の診断は支持され、Case 2にも複合コマンドの終了コード0が途中の検査失敗を隠す例があることが追加で確認されました。Reviewerは、失敗・訂正・復旧条件を保持した評価記録の取り込みと、今回の3ページの利用を承認しています。無介入の大量生成・自動納品の安定性まで含む承認ではありません。

## スキルへ反映した改善

| 観察された問題 | 反映先と変更 |
|---|---|
| 生成例の図が機構説明を十分に支えない | [原図選定](../../references/figure-extraction.md)に、中心命題と候補図が示す関係を比較する実施例を統合。仕組み・出力品質・用途に応じて関連本文も読む |
| 比較欄で異なる対象・粒度が混在 | [研究紹介の執筆](../../references/research-slide-writing.md)に、入力・内部表現・生成処理・最終出力・用途を区別する例を統合。固定の必須列にはしない |
| 見出しの否定が本文の主張範囲より広い | 同執筆ガイドで、表現と出力を区別し、操作を具体化した見出しへ推敲する例を追加 |
| Oursの帰属、抽象的な要点、小字 | 原図の表記を保持した隣接図注、要点と具体操作・差異の対応、注釈を含む実表示確認を既存手順へ統合 |
| ページ担当と監督者の採用責任が曖昧 | 図選定は担当範囲内で自律判断し、監督者は全体整合と公開時の確認を担うと明確化 |
| 書き出し成功と正式検査・意味レビューが混ざる | [委任・統合](../../references/management-workflow.md)で、実施検証と未実施理由を既存メモ・正本参照で返す責任を明確化 |

追加の必須台帳・プロパティ・図数・固定表・承認工程は設けていません。改訂を初回生成物へ遡って適用したり、結果を良くするために抽出をやり直したりしていません。

制作過程レビューの追加指摘は、既存の返却手順へ統合しました。各検査の結果を個別に確認することと、過程を評価するタスクでは初回・最終版と意味が変わる主要な修正前後・理由を既存メモや版管理で保持することです。通常の制作に全操作の記録を義務づけるものではありません。この限定変更も独立Reviewerが承認し、単一ページ評価に関する改訂とレビューを終了しました。

# 再構成した視覚表現のレビュー

この文書は、サーベイ作成者が描き直し、導出、正規化、解釈、統合した、主張を担う視覚表現の許可と意味忠実性を定めます。原図候補の取得は[原図の取得](figure-extraction.md)、経路・属性・パケットの機械条件は[視覚表現の契約](evidence-visual-contract.md)、一般的な見た目の検査は[視覚レビュー](visual-review.md)、公開判定の組合せは[レビュー基準](review-rubric.md)を参照します。

## 対象と役割による許可

**文献紹介スライドでは、サーベイ作成者による再構成を使いません。** 原図の忠実な描き直し、原資料の文章から作った図、原資料に基づくものの配置・矢印・数値・ラベルを作成者が作った図も含みます。原図を示すか、図を使わず文章・表で根拠を説明します。独立した視覚表現を使えるのは、スライドの実際の役割がサーベイ独自の統合・解釈であり、その帰属を読者に明示する場合です。文献紹介に「サーベイ独自」とラベルを付けるだけでは役割は変わりません。

対象は図式、グラフ、表、原図の描き直し、および主張を担う矢印、数値、ラベル、軸、凡例、注釈、セルです。装飾は本当に装飾である間だけ対象外です。装飾のように作った矢印でも関係を伝えるなら、主張を担う要素として扱います。

| 分類 | 意味と境界 |
|---|---|
| 原図 | 原資料の作成者による図を帰属付きで読者に示す |
| 忠実な再構成 | 対応原図があり、許可された理由でサーベイ作成者が描き直す。原資料の作成物にはならない |
| 文章由来の再構成 | 対応原図がなく、原資料の文章・表・記述データから視覚表現を作る。解釈の検証負担が高く、忠実な原図とは扱わない |
| サーベイ独自の統合 | 複数資料をまたぐ比較・解釈を表す。原著者の図として示さない |

分類は図全体について、来歴と支持は要素ごとに確認します。キャプションは読者向けの説明、要素対応表は監査用の記録です。どちらも「サーベイで再構成」という一言では代替できません。

一ページに独立した複数の原図を並べる配置は、それだけではサーベイ作成者による再構成や統合図へ分類しません。各原図を別の視覚使用として、原図位置・出典・要約・評価・留保との対応を確認します。原資料の複数パネルが一つの関係を示す場合と、別々の原図を配置した場合を区別します。ページ内の全使用は[任意の `visuals` 配列](evidence-visual-contract.md#一ページに複数の視覚使用を含める)で渡し、再構成が含まれる場合だけ該当する使用に比較パケットと要素対応表を適用します。ページ全体へ一つの経路や状態を割り当てて、未確認の図を他の図の通過状態で覆いません。

## 役割と経路の対応

`source_visual_route` はG4-Vの原図経路です。読者表現の `kind`（`diagram`、`chart`、`table` など）でも、原資料が報告した図であることの証明でもありません。一つの経路を選び、読者向けの分類を別に記録します。

| 状況 | `source_visual_route` | 読者向けの分類 | 意味レビューへ渡す根拠 |
|---|---|---|---|
| 対応する原図をそのまま示す | `source_figure` | 原図 | 原図位置、切り出し、帰属、通常の原図レビュー |
| 対応原図を忠実に描き直す | `faithful_reconstruction` | 忠実な再構成 | 原図切り出し、許可理由、比較パケット、サーベイ制作の帰属。実際の役割がサーベイ独自のスライドに限る |
| 対応図がなく文章・表・記述データから作る | `no_useful_candidate` | 文章由来の再構成 | 走査記録、正確な文章・データ位置、キャプション、要素対応表 |
| 最終的な統合の形成に原図候補を使わない | `no_useful_candidate` | サーベイ独自の統合 | 最終関係を表す原図がない理由を記した走査記録。G4-Vで必要な構成資料の切り出しは監査資料に保持 |
| 原図候補を資料間統合の比較・根拠に実際に使う | `new_explanatory_visual` | 独自統合・資料間比較 | `cross_source_comparison` または `review_synthesis`、使用原図、比較パケット、サーベイ制作の帰属 |

最後の2行は、原図候補を実際に使うかによって分かれます。構成資料の切り出しが監査資料に存在するだけでは `new_explanatory_visual` になりません。単に原図を保存しなかったことを候補なしとしないでください。`new_explanatory_visual + no_useful_candidate` のような複合値は使いません。

既存の `faithful_reconstruction` と `no_source_figure` の組合せは[機械契約の互換経路](evidence-visual-contract.md#原図経路と条件付き属性)として残りますが、文章由来の再構成や候補原図を使わない統合をその経路へ分類し直す許可ではありません。どの経路でも、文献紹介の役割による禁止は優先します。独自統合のスライドは、比較・解釈を実際の説明上の役割としなければなりません。

## 原図対応と要素の来歴

図全体では、対応原図の有無、分類、根拠とした原図・文章・データ、正確な位置を記録します。位置は安定したページ番号と章・節・見出し・図表番号などを組み合わせます。版によってページが異なる場合は版を特定し、安定した節・表位置も保持します。「論文に基づく」だけでは根拠位置になりません。

主張を担う再構成ごとに、一つの監査用要素対応表を一つの `visual_id` と `slide_id` へ結びます。JSONまたは同等の項目を持つ表を使えます。これはパケット内のレビュー資料であり、新しい普遍的なマニフェスト属性や検証器スキーマではありません。各行には少なくとも次を記録します。

- 表示要素とその種類：`edge`、`node`、`number`、`label`、`axis`、`legend`、`annotation`、`table_cell` または同等の種類。
- 要素が伝える主張・観測・関係、`relation_type`、必要なら人が読める `relation_label`。
- 要素の `origin` と、それを支える原資料ID・正確なページ／節／図／表／データ位置。
- 数値の場合は、その数量に適用する単位・尺度、分母、集約、時点・条件、不確実性、導出入力と演算。適用条件は[定量属性の定義](evidence-model.md#定量的な根拠主張だけに用いる属性)に従い、分母は比率・割合・率など、数量の意味に必要な場合だけ記録。
- レビュー状態、未解決の問い、支持を確認できていない要素の修正。

`origin` と `source_support` は別の役割を持ちます。

| 項目 | 意味 |
|---|---|
| `origin` | 表示内容・変換を誰が作ったか。`source-preserved`、`survey-adapted-or-normalized`、`survey-added-or-interpreted` または同等の明示状態 |
| `source_support` | 主張を支える原図・文章・表・データと、その位置 |

サーベイ追加要素にも明示的な解釈を支える原資料があり得ますが、支持があることは原著者がその要素を作ったことを意味しません。図全体の帰属が正しくても、その内部の矢印や数値が未支持であれば別に修正します。

図式・表・グラフの契約に同じ要素の意味がある場合は、それを参照して由来と支持を確認します。同じ定義を対応表へ再入力する必要はありません。全要素で共通する単位・条件・根拠はまとめて参照し、異なる値や支持だけ要素ごとに区別します。対応表の詳細から比較パケットと読者向けキャプションを作る場合も、同一の判断を独立して更新しません。

## 読者向けキャプション

キャプションは、監査資料を開かずに原資料の内容とサーベイ側の選択を区別できる説明です。視覚表現の複雑さに応じて、次の内容を明記します。

1. 引用した原資料に対応図があるか。
2. 原図、忠実な再構成、文章由来の再構成、独自統合のどれか。
3. 使用したデータ・原図・文章と、正確なページ・章・節・見出し・図表位置。
4. 意味を担う要素または曖昧さのない要素群のうち、原資料から保持したものと、追加・削除・正規化・解釈したもの。行ごとの位置は対応表に置けるが、変更の開示を全て対応表へ隠さない。
5. 自明でない矢印、数値、ラベル、関係型の意味。
6. サーベイが追加・変換した要素に誤りがある場合の帰属先。

以下は記録例の文型です。括弧内を実際の位置・説明に置き換えます。

```text
［著者、年、図X、p. Y］の忠実な再構成。対応原図があります。原資料の関係、値、
単位、条件を保持しています。原資料から保持した意味要素：［ノード・辺・値・
ラベル、または一意に分かる要素群］。サーベイで追加・正規化した意味要素：
［一覧、または「なし」］。描き直しはサーベイ作成者によるもので、要素ごとの
根拠位置とレビューは監査用対応表に記録しています。追加部分の誤りは原著者
ではなくサーベイ側に帰属します。
```

```text
サーベイ独自の文章由来の図式。［著者、年］の原資料には対応図がありません。
［章・節・見出し、p. Y、表・データ位置］から作成しました。ノードと［関係の
名称、例：統計的関連］は当該箇所に対するサーベイの解釈であり、原資料が報告
した図ではありません。各矢印・数値・ラベルの根拠は要素対応表に記録しています。
```

```text
サーベイ独自の資料間統合。最終的な関係を表す単一の原図はありません。
［資料Aの正確な位置］と［資料Bの正確な位置］に基づきます。［矢印・正規化・
導出値］はサーベイによる統合で、いずれかの原著者の作成物としては示して
いません。引用した原図切り出しと要素ごとの支持は監査資料に保持しています。
```

文章由来と資料間統合の例は、実際の役割がサーベイ独自の統合・解釈である場合だけ使えます。キャプションによって文献紹介での再構成を許可しません。

## 要素対応表と意味の検証

全体の似方だけで判断せず、意味を担う全要素を行ごとに確認します。

| 要素 | 最低限確認する問い |
|---|---|
| 矢印・辺 | 両端が引用根拠にあり、関係が支持され、方向と意味が明示されているか |
| ノード・カテゴリ・ラベル | 構成概念、カテゴリ、名称、範囲の由来が原資料保持かサーベイ追加か、読者に分かるか |
| 数値・値 | 引用値または出典入力からの透明な導出か。その数量に適用し、解釈に必要な単位・尺度、分母、集約、時点、条件、不確実性を確認できるか |
| 軸・凡例・セル | 尺度、カテゴリ、セル意味、向き、欠測の扱いが原資料と一致するか |
| 注釈・強調 | 記述が支持され、配置が根拠より強い関係を暗示していないか |

AからBへの矢印には、原資料が示すAとBの関係が必要です。単なる共起、文章中の隣接、もっともらしい説明だけでは足りません。因果として読むなら因果の根拠が必要で、統計的関連ならそう明記します。時間、分類、比較、集約、読む順序も区別し、[契約の関係語彙](evidence-visual-contract.md#図式diagramcontract)を使います。統計的関連は既存の `relation_type=other_explicit` を保持し、人が読める `relation_label` に「統計的関連」と記します。この整理のために制御語彙を拡張しません。

数値は原資料の精度を保持し、範囲、割合、件数、推定値を黙って精密な値へ変換しません。導出値は出典付き入力と演算を示します。[定量属性の定義](evidence-model.md#定量的な根拠主張だけに用いる属性)に照らし、その数量に適用し解釈に必要な分母、単位・尺度、期間、条件、不確実性、集約の情報が得られない場合は「原資料に記載なし」と示すか、値を除きます。平均や係数などに適用しない分母は該当外であり、未報告とみなしたり、それを理由に値を除いたりしません。標本数が解釈を変える場合は分母とは分けて原資料の方法・条件から確認します。未確認の値を推測で補いません。

ラベル・ノードには支持されない構成概念、カテゴリ、機序、方向を導入しません。軸・凡例も解釈を変えるため、文章と同じ位置・由来レビューを行います。原資料が区別していないカテゴリを作る場合は、サーベイ独自解釈と明示し、その解釈を支持する根拠を示します。

## G4-VからG6への引継ぎ

### G4-V：役割と検証負担を判断する

1. [原図の取得](figure-extraction.md)に従い、関連する図・表・方法・結果・文章を確認し、経路と候補・走査の根拠を記録します。
2. 配置前に役割による許可を判断します。独自統合なら、統合・解釈の役割と、独立した図によって何を検査できるかを述べます。
3. 上の対応表で経路を選び、読者の読みやすさ、資料間比較、独自統合の便益を、取得、原図との対、全要素のレビュー、解釈の主観性の負担と比較します。
4. G5前にキャプション案と要素対応表を作り、支持できない要素を見た目の調整前に除きます。

### G5：役割と帰属を表示へ反映する

適用する原図切り出し・走査記録、派生素材、比較パケット、キャプション、要素対応表を、`visual_id` と `slide_id` で結びます。全ての意味要素に支持と由来の判断がある状態で制作します。監査ID・工程の記録は読者向け表示へ出さず、原資料とサーベイの帰属はキャプションに残します。

文章と図の役割の分担は[制作契約](presentation-build-contract.md#文章と図の役割)に従います。本文を繰り返すだけの図は、除去、原図・文章・表への置換、または実際の役割を独自統合へ修正してから制作します。

### G6：キャプションと全要素を独立にレビューする

最初に読者向け成果物だけを渡し、その後に学術・原資料忠実性の資料を渡します。各再構成には、適用する原図切り出しまたは走査記録、文章・データ位置、派生図、比較パケット、キャプション、要素対応表を含めます。レビュー担当者は次を確認します。

- スライドの実際の役割と分類が一致し、文献紹介にサーベイ再構成が含まれないこと。
- キャプションが原図対応、根拠位置、保持・変更内容、帰属を説明すること。
- 対応表の全行と全矢印・数値・ラベル・軸・凡例・注釈・主張セルを原資料の支持と比較できること。
- 根拠以上の因果や精度を暗示せず、修正と再確認条件を記録し、原資料の誤りとサーベイの変換・解釈を区別すること。

キャプション、正確な位置、要素対応表をレビューするまでは `visual_review_status=passed` にできません。対応表の欠落・不完全・未レビューは手動のG6公開阻害条件であり、新たな決定論的検査器の条件にはしません。`no_useful_candidate` の走査記録は要素対応表や文章位置の代用ではありません。原図を使う経路では原図切り出しと比較パケットも保持します。

## 判定と修正条件

次の場合は公開を止めるか、修正へ戻します。

- 文献紹介で忠実な描き直しを含むサーベイ再構成を使っている。
- 対応原図の有無、根拠とした原図・文章・データ、正確な位置がキャプションにない。
- 意味要素の対応表行、原資料の支持、由来、レビュー状態が欠けている。
- 両端・方向・意味を支持する関係がない、または統計的関連を因果として示している。
- その数量に適用し解釈に影響する単位・尺度、分母、集約、条件、時点、不確実性、導出の情報が数値にない。
- 経路が根拠パケットと矛盾し、排他的な経路を組み合わせ、または原図なし例外で文章由来・独自統合を隠している。
- キャプションと対応表を読んでも、原資料の報告とサーベイの解釈を区別できない。

装飾という呼称で主張要素のレビューを避けません。指摘、重要度、正確な図・要素位置、修正、再確認条件を記録します。整った描画、埋まったマニフェスト、決定論的検査の通過は、未解決の要素来歴・意味の問題を補いません。意味、忠実性、視覚レビューの状態は個別に保持し、[レビュー基準](review-rubric.md)の公開条件の論理積で判定します。
